# P2 资产闭环审查修复计划

本计划对应 `48b6e02` 完成后的四项审查问题，完成条件是代码、回归测试、资产队列文档和提交同时落地。

## 修复项

1. **取消后的正式绑定**：`RunHandle::stop` 与串行绑定共享绑定门闩。绑定必须持锁检查取消状态后才能修改正式项目文件；`stop` 返回后不会再有资产提升或场景改写。
2. **Artifact 操作并发覆盖**：调度器与删除、手动提升命令共享队列写锁，所有队列文件的读改写均串行执行，避免旧快照覆盖用户操作。
3. **同场景同类型多资产**：场景命令写入任务 ID 标记；重跑只替换该任务自己的命令。目标文件名冲突时追加任务 ID，避免两个合法任务共享并覆盖同一正式文件。
4. **恢复后的降级来源**：attempt 和 task 持久化 `usedLocalFallback`，最终告警从完整队列计算，不依赖本次恢复调用的临时状态。

## 验收

- 回归测试分别覆盖绑定门闩取消竞态、Artifact 命令与运行队列互斥、相同 `targetStem` 的同类任务、恢复后占位素材来源。
- Rust 全量测试、前端 Vitest、前端生产构建和 `git diff --check` 通过。
- 更新 AssetTaskQueue 数据契约与运行语义文档。
- 只提交本修复范围，保留用户已有的无关工作区改动。

## 锁粒度

当前产品流程同一进程只运行一个项目生成任务，因此使用一个进程级队列写锁。若后续支持多项目并行生成，再将其替换为按规范化项目路径分片的锁表。
